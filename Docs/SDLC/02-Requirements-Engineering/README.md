## Suggested reading order

1. Read the project scope and SRS overview.
2. Open only the domain needed for the feature under discussion.
3. Find its work item in the backlog and its criterion in the traceability matrix.
4. Consult scenarios, data definitions and dated evidence when a specific question requires them.

## How to interpret the records

- **SRS:** owns requirement wording and acceptance criteria.
- **Backlog:** owns work breakdown and dependencies; linked issues and the board hold execution status.
- **Traceability matrix:** connects requirements, design and verification evidence.
- **Historical evidence:** describes the revision and date inspected; it does not establish current runtime readiness.

Keep selected MVP behavior separate from deferred proposals. A documented design or completed document does not prove implementation, test success or release acceptance.
