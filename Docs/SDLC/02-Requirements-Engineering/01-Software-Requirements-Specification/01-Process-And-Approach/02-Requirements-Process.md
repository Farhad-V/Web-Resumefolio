# Requirements Process

Work on one MVP behavior at a time. Use the [selected scope and criteria](https://github.com/Farhad-V/Web-Resumefolio/blob/1f2acaa351ac306cb57cbe4fe9742e8bd90720d9/docs/MVP/baseline/criterion-dispositions.md) to decide what belongs in the release.

| Activity | What to do in Resumefolio |
| --- | --- |
| **Discover** | Identify the actor, need and source. Record confirmed input and open questions in the [elicitation log](../02-Stakeholders-And-Elicitation/02-Elicitation-Log.md#stakeholders-and-elicitation-elicitation-log). |
| **Analyze and agree** | Resolve conflicting needs, check [feasibility](01-Feasibility-Study.md#process-and-approach-02-feasibility-study), and decide what is required for MVP. Record the choice and its reason in the [decision index](../07-Change-And-Baseline/03-Requirements-Questions-And-Decisions.md#change-and-baseline-open-questions-and-decisions). |
| **Specify** | In the [SRS](../03-Requirements-Specification/17-Software-Requirements-Specification.md#requirements-specification-requirements-specification), give each requirement a stable ID, an observable outcome and acceptance criteria. Include applicable quality targets and constraints. |
| **Validate** | Walk through success, denied access and failure with the intended actor. Check that the requirement is testable and record findings and actual evidence in [validation](../06-Validation-And-Traceability/07-Validation-And-Traceability.md#validation-and-traceability-validation-and-traceability). |
| **Manage changes** | Keep the ID and baseline history. Use [change control](../07-Change-And-Baseline/02-Requirements-Change-Control.md#change-and-baseline-change-control) to update affected requirements, design and tests when a decision changes. |

**Before baselining:** Check that each requirement answers a real need, has one clear meaning, fits the constraints, agrees with related requirements, has a known priority and can be traced and tested.
