# Requirement Priority and Readiness

Use the [157-row requirement register](../../../baseline/requirement-register.csv) and [470-row criterion register](../../../baseline/criterion-dispositions.csv) as the current scope/priority records. Original IDs and criterion wording are preserved; a mixed requirement selects only its explicit MVP slice. [Criterion guide](../../../baseline/criterion-dispositions.md).

| Classification | Meaning |
| --- | --- |
| Must within MVP slice | Required for the selected Core/basic ProjectForge outcome, subject to its exact criterion constraint |
| Later | After MVP; not a current Release prerequisite |

Priority is not a completed test or an implementation order. [Technical and policy decisions](../../../baseline/README.md) are selected; [implementation gates](../../../baseline/implementation-sequence.md) identify unexecuted environment, security, actor, operational and quality checks. [Backlog dependencies](../../../Project-Management/product-backlog.md) and GitHub track actual execution.

Do not infer that all criteria of a selected parent are accepted, or require future mail/calendar/review/Sprint/runner behavior merely because a shared access or recovery rule names it. Do not keep a second proposed-priority table that contradicts the selected registers.
