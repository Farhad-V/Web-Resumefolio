## 1. Meaning and Authority

FAU V02 slide 19 uses Must / Should / Could / Won't. Proposed Must below means a candidate supports an already agreed capability; it does not accept every proposed detail, invent an implementation order or prove feasibility. In particular, permission, lifecycle and failure details remain open in their primary records. Proposed classifications require individual review before adoption.

No agreed Version 1 capability is downgraded to Should/Could or removed to meet a date. Newly introduced refinements now have explicit draft classifications; individual necessity/source review and owner disposition are still required before adopting Must/Should/Could/Won't. There is no need to populate all four categories artificially. Existing product AI, automatic translation and automatic demo migration exclusions retain their accepted source decisions, rather than being allocated new candidate IDs.

Keep scope necessity, investigation urgency and implementation order separate. Investigate access isolation, actual submitted materials, provider feasibility, execution isolation and recovery dependencies before commitments that depend on them. No extra staffing, date or numerical severity is assigned here.

## 3. SMART Review in the Course's Meaning

| Attribute | Check before affected acceptance |
|---|---|
| Specific | One sufficiently clear outcome with actor/context and source; split compound independent goals. |
| Measurable | Observable result and decided threshold/conditions when quantitative; a reference to an undefined future policy is a blocker. |
| Assignable | Responsible owner/discipline identified; a solo owner does not imply separate staffed teams. |
| Realistic | Evidence supports the dependent feasibility commitment; investigation plans alone are insufficient. |
| Traceable | Stable unique reference and explicit source/criterion/scenario/analysis links appropriate to this stage. |

This uses the course's Assignable and Traceable, rather than substituting a different SMART expansion.

## 4. Readiness and Remaining Work

Candidate IDs already exist and are unique. Preserve them; settle the global notation through Q-D01 rather than renumbering to make the documentation appear final. A future FR/NFR convention is optional until explicitly selected; unique identity is the necessary property.

Review every proposed classification, resolve acceptance-blocking policies/targets, inspect actor outcomes and actual source coverage, and retain the real baseline disposition against an identifiable candidate. Missing future code or product test results do not by themselves fail this requirements-stage assessment.
